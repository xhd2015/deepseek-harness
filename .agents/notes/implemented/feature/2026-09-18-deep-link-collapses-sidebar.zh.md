# Agent Note: Session 深链收起侧边栏

Status: implemented

[English](2026-09-18-deep-link-collapses-sidebar.md) | 中文

## Problem

`dsh web open` 以及任何复制来的 `?session=` URL 都会在某个 Session 上打开 GUI，但框架总是先绘制 280px 的侧边栏。在新标签页中跟随深链的读者想要的是会话界面，而对一个已经指定 Session 的文档来说，Session 列表是多余的。

依赖 Host 列表来决策已经太晚，无法做到不可见：`bindSessionUrl` 只有在 Session 列表到达后才能结算深链，而这发生在框架首次绘制之后数百毫秒。实测结果是框架先绘制侧边栏、再把它动画移走——读者会看到布局抽动。`SidebarRoot` 本就能静态渲染冷启动的控制栏（其 `everWide` ref 只对*实时*收起做交叉淡入），因此修复方向是把决策提前，而不是把较晚的那次动画做得更好看。

## Decision

`ui-workspace` 在其条目激活时解析 `?session=`，若 id 合法便立即调用 `ctx.layout.collapseSidebar()`。客户端条目在渲染器挂载框架之前完成激活，因此框架首次渲染时存储已处于收起状态；控制栏就是首次绘制的几何形态，没有任何动画。`collapseSidebar` 是幂等的：在宽框架上把宽度偏好置零，在窄框架上清除展开覆盖，沿用 `toggleSidebar` 的两个分支而不做翻转。

该 id 是否在列表中不影响侧边栏。深链随后仍会依据 Host 列表结算：打开已列出的 Session，否则在该控制栏之上显示链接无效提示层。参数非法或缺失时保持默认框架，因为仅凭 URL 就能同步判定。应用内导航（点击行、搜索结果、新建会话、fork）发生在激活之后，绝不会收起。布局状态按文档存在（`createLayoutStore` 未声明持久化），因此收起不会进入其他页面或标签页，读者随后的开关对该文档拥有最终决定权。

本笔记的早期修订把收起限定在 id 能够解析的情况，因此只有*已列出* Session 的文档会收起。该规则只能在列表到达后运行，读者会看到它即将移除的面板；下文 Alternatives 记录了其他修法为何落败。现规则适用于任何全新文档，包括重新加载一个已带 `?session=` 的 URL（客户端会让它与当前选中保持同步）。

## Alternatives considered

**在深链命中分支中、列表结算之后收起（早期决策）。** 它让“未找到”的情况与之前逐字节一致，但结构上必然发生在首次绘制之后：浏览器场景记录到同一文档的框架先为 280px、后为 56px。为一个失效链接的框架宽度付出可见的抽动是错误的取舍。

**命中分支再加上失效链接的回滚展开。** 错误路径上同样存在绘制问题——先收起，待列表结算后再展开——因此除了多出第二个有方向的布局操作之外毫无收益。

**把框架首次绘制推迟到深链结算之后。** 既不抽动也无需猜测，但挂载要等待 Host 列表，而该列表并不保证到达（重连中或连接失败时）。硬门控可能让应用永远停在启动页，超时回退又会退回抽动，因此这些复杂度换不来确定性。

**让 Host 标记所服务的文档。** webserver 有 index 注入缝，Host 行可以标记“该 `?session=` id 已列出”，客户端据此在绘制前以正确答案收起。但该缝目前拿不到请求 URL，因此需要 webserver 把请求贯穿到每个注入监听者、需要 Host 插件读取 Session 注册表、还需要新的所服务文档提示——为一个纯视觉决策引入服务端与客户端契约，而仅凭 URL 本就能做出该决策。

**复用 `ctx.layout.toggleSidebar()`。** 它会翻转当前适用的分支：宽框架下已经收起（0）会被*展开*，窄框架会设置手动展开覆盖而不是清除它。侧边栏外壳正是出于同一原因，按自己掌握的状态把它限制为仅展开。

**让绘制后的收起改为瞬时切换而非动画。** 这只是治标：框架仍会绘制一个即将移除的侧边栏，而瞬时变体需要像 `rightbarInstant` 那样增加一个标志。

## Consequences

控制栏是深链文档绘制的首个几何形态。`apps/web/tests/deep-link-sidebar-collapse.e2e.ts` 从文档开始记录框架渲染过的每一个不同列轨道——已列出与未列出两种情况下都绝不能出现 `280px`——该断言在绘制后收起的实现上会失败，因此视觉回归是被固定住的，而不只是被描述。

参数合法但 id 未列出的 `?session=` 现在落在收起的框架上并显示链接无效提示，而此前落在展开的框架上。提示层说明了问题，一次开关即可恢复侧边栏，因此失效链接路径用一列宽度换来了其他所有场景下都没有动画。

没有任何持久化或对模型可见的变更：写入仅限于临时布局存储，不触及会话事件、线上载荷或持久化偏好。`packages/client/ui-workspace/tests/apply.client.spec.ts` 固定了哪些 URL 会请求收起，`packages/client/ui-layout/tests/layout-store.client.spec.ts` 与 `app-frame.client.spec.tsx` 固定了该操作与最终的轨道态。
